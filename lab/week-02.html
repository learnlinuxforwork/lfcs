Lab guide 2

Git, Services, and Performance Troubleshooting

The less obvious half of Essential Commands: version control, writing your own systemd unit, and finding what's slow.

8-10 hours Week 1 complete
Before you start
  • Git installed on both machines: sudo apt install -y git (Ubuntu) / sudo dnf install -y git (Rocky)
  • You can sudo on both machines

1. Git fundamentals

The exam expects you to operate a repo from the command line, not to explain what Git is.

Init, configure, and commit
mkdir ~/lfcs-repo && cd ~/lfcs-repo
git init
git config user.name "Lab User"
git config user.email "lab@example.com"
echo 'first line' > notes.txt
git add notes.txt
git commit -m 'first commit'
Branch, edit, and merge
git branch feature-a
git switch feature-a
echo 'branch change' >> notes.txt
git commit -am 'edit on feature-a'
git switch main 2>/dev/null || git switch master
git merge feature-a

2. Resolve a merge conflict

This will happen on the exam if it happens at all — practise the mechanical steps, not the theory.

Create a real conflict on purpose
git switch -c conflict-a
echo 'version A' > conflict.txt && git add conflict.txt && git commit -m 'A'
git switch main 2>/dev/null || git switch master
git switch -c conflict-b
echo 'version B' > conflict.txt && git add conflict.txt && git commit -m 'B'
git switch main 2>/dev/null || git switch master
git merge conflict-a
git merge conflict-b
Resolve it and finish the merge
cat conflict.txt
echo 'resolved content' > conflict.txt
git add conflict.txt
git commit -m 'resolve conflict'

3. Write a custom systemd service

Services you write yourself, not just ones you enable, are testable.

Create a tiny long-running script and a unit for it
sudo tee /usr/local/bin/lfcs-heartbeat.sh >/dev/null <<'EOF'
#!/usr/bin/env bash
while true; do echo "heartbeat $(date)" >> /var/log/lfcs-heartbeat.log; sleep 30; done
EOF
sudo chmod +x /usr/local/bin/lfcs-heartbeat.sh
The unit file (identical on both distros)
sudo tee /etc/systemd/system/lfcs-heartbeat.service >/dev/null <<'EOF'
[Unit]
Description=LFCS lab heartbeat

[Service]
ExecStart=/usr/local/bin/lfcs-heartbeat.sh
Restart=always

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now lfcs-heartbeat.service
systemctl status lfcs-heartbeat.service --no-pager

4. Find what's slow

top, ps, and free in that order — resource hog, then confirm with the process table, then confirm memory pressure.

Live view, then a one-shot snapshot
top -bn1 | head -15
ps aux --sort=-%cpu | head -6
free -h
Watch the heartbeat service you just created
ps aux | grep lfcs-heartbeat | grep -v grep
tail -5 /var/log/lfcs-heartbeat.log

5. SSL certificates

You won't run a CA on the exam, but you will be expected to generate and inspect a certificate.

Generate a self-signed cert and inspect it (identical on both distros)
openssl req -x509 -nodes -newkey rsa:2048 \
  -keyout ~/lab02.key -out ~/lab02.crt -days 365 \
  -subj "/CN=lab02.local"
openssl x509 -in ~/lab02.crt -noout -subject -dates

6. Constrain a process

nice/renice for scheduling priority, and a resource limit at the systemd level.

Lower a process's priority
sleep 300 &
ps -o pid,ni,cmd -p $!
renice 10 -p $!
ps -o pid,ni,cmd -p $!
kill $!
Cap memory for a systemd service (identical on both distros)
sudo systemctl edit lfcs-heartbeat.service --force --full <<'EOF'
[Unit]
Description=LFCS lab heartbeat

[Service]
ExecStart=/usr/local/bin/lfcs-heartbeat.sh
Restart=always
MemoryMax=50M

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl restart lfcs-heartbeat.service

Verify your work

Run these before you consider the lab finished.

  1. git log --oneline # both commits and the resolved merge are present
  2. systemctl is-active lfcs-heartbeat.service
  3. openssl x509 -in ~/lab02.crt -noout -subject
  4. systemctl show lfcs-heartbeat.service -p MemoryMax
Break it, then fix it

Break:

sudo systemctl edit lfcs-heartbeat.service --force --full
# delete the [Service] block entirely, save

What you'll see: systemctl daemon-reload succeeds but the service fails to start — systemd complains the unit has no ExecStart.

Fix:

sudo systemctl edit lfcs-heartbeat.service --force --full
# restore ExecStart=/usr/local/bin/lfcs-heartbeat.sh, save
sudo systemctl daemon-reload
sudo systemctl restart lfcs-heartbeat.service

Why it matters: A unit file with no ExecStart is a common self-inflicted wound after an edit. Reading the exact systemctl status error and mapping it back to the missing directive is the actual skill.
