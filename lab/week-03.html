Lab guide 3

Users, Groups, and Access Control

The smallest domain by weight, easy marks if you get sudo, ACLs, and limits right.

8-10 hours Week 2 complete
Before you start
  • Both machines up
  • You can sudo on both

1. Create and manage users and groups

Same commands on both distros — this is genuinely distro-neutral territory.

Create, add to a group, and set a password (identical on both distros)
sudo groupadd lfcs-admins
sudo useradd -m -G lfcs-admins -s /bin/bash lfcsuser
sudo passwd lfcsuser
id lfcsuser
Modify and delete
sudo usermod -aG sudo lfcsuser 2>/dev/null || sudo usermod -aG wheel lfcsuser
sudo userdel -r lfcsuser 2>/dev/null; echo 'delete tested, recreate for the rest of this lab'
sudo useradd -m -G lfcs-admins -s /bin/bash lfcsuser
sudo passwd lfcsuser

2. Configure sudo

A malformed sudoers file locks out privilege escalation for everyone — always edit with visudo.

Grant lfcsuser passwordless sudo for one command (identical on both distros)
echo 'lfcsuser ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart lfcs-heartbeat.service' | sudo EDITOR='tee' visudo -f /etc/sudoers.d/lfcsuser
sudo visudo -c
Test it as that user
sudo -u lfcsuser sudo -n systemctl restart lfcs-heartbeat.service && echo 'sudo rule works'

3. Password aging and account locking

Aging policy and locking are both tested, and both are easy to get backwards under pressure.

Set aging, then lock and unlock (identical on both distros)
sudo chage -M 90 -W 14 lfcsuser
sudo chage -l lfcsuser
sudo passwd -l lfcsuser
sudo passwd -S lfcsuser
sudo passwd -u lfcsuser

4. Environment and shell profiles

System-wide defaults live in one place, per-user overrides in another. Know which wins.

A system-wide variable for everyone, and a per-user override
echo 'export LFCS_LAB=system-wide' | sudo tee /etc/profile.d/lfcs-lab.sh
sudo chmod +x /etc/profile.d/lfcs-lab.sh
sudo -u lfcsuser bash -lc 'echo $LFCS_LAB'
sudo -u lfcsuser bash -c "echo 'export LFCS_LAB=per-user' >> ~lfcsuser/.bashrc"
sudo -u lfcsuser bash -lc 'echo $LFCS_LAB'

5. Resource limits

ulimit for the current shell, limits.conf for a persistent policy.

Check and set a limit for the current session
ulimit -n
ulimit -n 2048
ulimit -n
Make it persistent for lfcsuser (identical on both distros)
echo 'lfcsuser soft nofile 4096' | sudo tee -a /etc/security/limits.conf
echo 'lfcsuser hard nofile 8192' | sudo tee -a /etc/security/limits.conf

6. Access control lists

Grant one extra user access to a shared directory without touching the owning group.

Set and read default + explicit ACLs (identical on both distros)
mkdir -p /tmp/shared-lab03
sudo setfacl -d -m g:lfcs-admins:rwx /tmp/shared-lab03
sudo setfacl -m u:lfcsuser:rwx /tmp/shared-lab03
getfacl /tmp/shared-lab03

7. Bind to LDAP for centralized authentication

You won't have a real LDAP server to bind to in most home labs, so this step confirms the tooling is installed and configured correctly — SSSD does the actual work on both distros.

Ubuntu / Debian — Install SSSD tooling
sudo apt install -y sssd sssd-tools libnss-sss libpam-sss
sudo authselect select sss 2>/dev/null || echo 'authselect is a Rocky/RHEL tool — Ubuntu uses pam-auth-update instead'
sudo pam-auth-update --enable sss
Rocky / RHEL — Install SSSD tooling
sudo dnf install -y sssd sssd-tools oddjob-mkhomedir
sudo authselect select sssd --force
sudo authselect enable-feature with-mkhomedir

Verify your work

Run these before you consider the lab finished.

  1. id lfcsuser # user exists, in lfcs-admins
  2. sudo visudo -c # sudoers syntax is clean
  3. sudo passwd -S lfcsuser # account is unlocked, aging set
  4. getfacl /tmp/shared-lab03 | grep lfcsuser
Break it, then fix it

Break:

echo 'lfcsuser ALL=(ALL) NOPASSWD ALL extra garbage here' | sudo tee /etc/sudoers.d/broken

What you'll see: sudo itself starts refusing every command, for every user, with a syntax error on load.

Fix:

sudo visudo -c
# it will name the broken file
sudo rm /etc/sudoers.d/broken

Why it matters: This is exactly why you always edit sudoers files through visudo — it validates syntax before saving and refuses to let you lock yourself out. A raw editor won't stop you.
