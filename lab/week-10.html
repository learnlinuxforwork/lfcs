Lab guide 10

Firewalls, Routing, Bonding, and Load Balancing

The second half of Networking — everything after the packet leaves the box.

10-12 hours Week 9 complete
Before you start
  • Both machines up and reachable
  • You've noted each machine's IP from last week

1. Filter traffic with a firewall

Rocky ships firewalld by default; Ubuntu ships ufw on top of nftables. Learn to read both.

Ubuntu / Debian — ufw
sudo ufw status verbose
sudo ufw allow 2222/tcp comment 'lfcs ssh'
sudo ufw allow from 192.168.56.0/24 to any port 80 proto tcp
sudo ufw enable
sudo ufw status numbered
Rocky / RHEL — firewalld
sudo firewall-cmd --state
sudo firewall-cmd --permanent --add-port=2222/tcp
sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=192.168.56.0/24 port port=80 protocol=tcp accept'
sudo firewall-cmd --reload
sudo firewall-cmd --list-all

2. Read the same rules at the nftables level

Both ufw and firewalld are front ends over nftables — knowing the underlying layer is what separates memorizing from understanding.

Look underneath the front end
sudo nft list ruleset | head -30

3. Static routing

The concept and commands are identical everywhere — routing doesn't know what distro it's running on.

Read the routing table, then add a static route
ip route show
sudo ip route add 10.10.10.0/24 via 192.168.56.1 dev eth1
ip route show | grep 10.10.10
sudo ip route del 10.10.10.0/24

4. Interface bonding

Same bonding driver, same modes, on both distros — only the persistence layer differs slightly.

Create an active-backup bond from two interfaces (adjust interface names to your lab)
sudo modprobe bonding
sudo ip link add bond0 type bond mode active-backup
sudo ip link set eth1 down && sudo ip link set eth1 master bond0
sudo ip link set eth2 down && sudo ip link set eth2 master bond0
sudo ip link set bond0 up
cat /proc/net/bonding/bond0 | head -15

5. A basic HAProxy load balancer

Same package, same config file, same syntax on both distros.

Install HAProxy and front two backend hosts
sudo apt install -y haproxy 2>/dev/null || sudo dnf install -y haproxy
sudo tee -a /etc/haproxy/haproxy.cfg >/dev/null <<'EOF'

frontend lfcs_front
    bind *:8080
    default_backend lfcs_back

backend lfcs_back
    balance roundrobin
    server web1 <server-a-ip>:80 check
    server web2 <server-b-ip>:80 check
EOF
sudo systemctl enable --now haproxy
curl -s http://localhost:8080/ | head -3

6. Confirm it's actually working with tcpdump

The exam rewards proving a rule works, not just writing it.

Capture a few packets while you hit the load balancer
sudo apt install -y tcpdump 2>/dev/null || sudo dnf install -y tcpdump
sudo timeout 5 tcpdump -i any port 8080 -c 5 &
sleep 1
curl -s http://localhost:8080/ >/dev/null
wait

Verify your work

Run these before you consider the lab finished.

  1. sudo ufw status | grep 2222 || sudo firewall-cmd --list-ports | grep 2222
  2. ip route show | grep 192.168.56
  3. cat /proc/net/bonding/bond0 | grep 'Currently Active Slave'
  4. curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/
Break it, then fix it

Break:

sudo ufw deny 8080/tcp 2>/dev/null; sudo firewall-cmd --permanent --add-port=8080/tcp --remove 2>/dev/null; sudo firewall-cmd --permanent --remove-port=8080/tcp 2>/dev/null; sudo firewall-cmd --reload 2>/dev/null

What you'll see: curl against the load balancer's port now hangs or is refused, even though HAProxy itself is running fine — the firewall is silently dropping the traffic before it ever reaches the service.

Fix:

sudo ufw allow 8080/tcp 2>/dev/null
sudo firewall-cmd --permanent --add-port=8080/tcp 2>/dev/null && sudo firewall-cmd --reload 2>/dev/null

Why it matters: A service being 'up' and a service being reachable are two different facts, and the exam tests the gap between them constantly. Always check the firewall before you start debugging the application.
