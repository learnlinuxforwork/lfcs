Lab guide 9

IP Addressing, DNS, and SSH

The first half of the exam's biggest domain: get two machines talking and resolving names correctly.

8-10 hours Week 8 complete
Before you start
  • Both machines up
  • You know the interface name on each: ip link

1. Configure a static IPv4 address

Ubuntu owns networking through netplan/systemd-networkd; Rocky through NetworkManager.

Ubuntu / Debian — netplan (adjust the interface name and addresses to your lab)
cat /etc/netplan/*.yaml
sudo tee /etc/netplan/99-lfcs-lab.yaml >/dev/null <<'EOF'
network:
  version: 2
  ethernets:
    eth1:
      addresses: [192.168.56.10/24]
      dhcp4: false
EOF
sudo netplan apply
ip addr show eth1
Rocky / RHEL — nmcli
nmcli con show
sudo nmcli con add type ethernet ifname eth1 con-name lfcs-lab ip4 192.168.56.11/24
sudo nmcli con up lfcs-lab
ip addr show eth1

2. Add an IPv6 address alongside it

Same tools, same workflow, one more address family.

Ubuntu / Debian — netplan
sudo sed -i '/eth1:/a\      addresses: [192.168.56.10/24, fd00:lfcs::10/64]' /etc/netplan/99-lfcs-lab.yaml
sudo netplan apply
ip -6 addr show eth1
Rocky / RHEL — nmcli
sudo nmcli con mod lfcs-lab ipv6.method manual ipv6.addresses fd00:lfcs::11/64
sudo nmcli con up lfcs-lab
ip -6 addr show eth1

3. DNS resolution

Both distros lean on systemd-resolved or plain /etc/resolv.conf — check which one you actually have before editing.

Check what's managing resolution, then confirm it works
resolvectl status 2>/dev/null | head -10 || cat /etc/resolv.conf
getent hosts localhost
dig +short example.com 2>/dev/null || nslookup example.com

4. Time synchronization with chrony

Identical tool and config file location on both distros — a rare gift.

Install if needed, then check sync status
sudo apt install -y chrony 2>/dev/null || sudo dnf install -y chrony
sudo systemctl enable --now chronyd
chronyc tracking
chronyc sources -v

5. Harden SSH

Same config file, same directives, on both distros.

Key-based auth, no root login, non-default port
ssh-keygen -t ed25519 -C 'lfcs-lab' -f ~/.ssh/lfcs_lab -N ''
ssh-copy-id -i ~/.ssh/lfcs_lab.pub $(whoami)@<other-machine-ip>
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sed -i 's/^#\?Port.*/Port 2222/' /etc/ssh/sshd_config
sudo systemctl restart sshd
ssh -p 2222 -i ~/.ssh/lfcs_lab $(whoami)@<other-machine-ip> 'echo connected'

6. Copy files over SSH

scp and rsync both ride on the SSH connection you just hardened.

Both tools, same target
scp -P 2222 -i ~/.ssh/lfcs_lab ~/lab01/perms.txt $(whoami)@<other-machine-ip>:/tmp/
rsync -avz -e 'ssh -p 2222 -i ~/.ssh/lfcs_lab' ~/lab01/ $(whoami)@<other-machine-ip>:/tmp/lab01-rsync/

7. Inspect connections and interfaces

ss and ip replace the old netstat and ifconfig — the exam expects the current tools.

Current sockets and interface state
ss -tulpn | head -15
ip -s link show eth1

Verify your work

Run these before you consider the lab finished.

  1. ip addr show eth1 # both IPv4 and IPv6 addresses present
  2. chronyc tracking | grep 'Leap status'
  3. sudo sshd -T | grep -i permitrootlogin # should read 'no'
  4. ss -tlnp | grep ':2222'
Break it, then fix it

Break:

sudo sed -i 's/^Port 2222/Port 22999/' /etc/ssh/sshd_config
sudo systemctl restart sshd

What you'll see: Every SSH connection to this machine on port 2222 now refuses — you're locked out unless you already have a session open or console access.

Fix:

# from an existing open session or the console:
sudo sed -i 's/^Port 22999/Port 2222/' /etc/ssh/sshd_config
sudo systemctl restart sshd

Why it matters: Never restart sshd on a change you haven't verified from a second session first. This is exactly why you keep one terminal connected while you test SSH config changes in another — the exam will not forgive locking yourself out.
