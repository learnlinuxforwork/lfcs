Lab guide 5

Processes and Scheduled Work

Manage what's running and when it runs, from a one-off cron job to a recurring systemd timer.

8-10 hours Week 4 complete
Before you start
  • Both machines up
  • You can sudo on both

1. List, prioritize, and terminate processes

Same commands on both distros — process management is a kernel-level concept.

List, sorted by CPU, then find and kill something safely
ps aux --sort=-%cpu | head -10
sleep 600 &
SLEEP_PID=$!
kill -0 $SLEEP_PID && echo "process $SLEEP_PID is running"
kill $SLEEP_PID
Force-kill only when a clean kill doesn't work
sleep 600 &
SLEEP_PID=$!
kill -SIGSTOP $SLEEP_PID
ps -o pid,stat,cmd -p $SLEEP_PID
kill -SIGKILL $SLEEP_PID

2. Priority and niceness

Lower the priority of something noisy without stopping it.

Start something at a lower priority, then re-nice a running one
nice -n 15 sleep 300 &
ps -o pid,ni,cmd -p $!
renice -n 5 -p $!
ps -o pid,ni,cmd -p $!
kill $!

3. One-time jobs with at

Different install step per distro, identical usage once it's installed.

Install at, queue a job, then inspect the queue (installs differ, usage doesn't)
which at || sudo apt install -y at 2>/dev/null || sudo dnf install -y at 2>/dev/null
sudo systemctl enable --now atd
echo 'echo at-job-ran >> /tmp/at-test.log' | at now + 2 minutes
atq
Confirm it ran
sleep 130
cat /tmp/at-test.log

4. Recurring jobs with cron

The five-field syntax is identical everywhere. Get comfortable reading it, not just writing it.

A user crontab and a system-wide drop-in
( crontab -l 2>/dev/null; echo '*/5 * * * * echo cron-user-ran >> /tmp/cron-user.log' ) | crontab -
crontab -l
echo '*/5 * * * * root echo cron-system-ran >> /tmp/cron-system.log' | sudo tee /etc/cron.d/lfcs-lab

5. systemd timers as a cron replacement

The exam expects you to know timers exist and can do the same job.

A timer + service pair (identical on both distros)
sudo tee /etc/systemd/system/lfcs-timer-test.service >/dev/null <<'EOF'
[Unit]
Description=LFCS timer test

[Service]
Type=oneshot
ExecStart=/bin/bash -c 'echo timer-ran >> /tmp/timer-test.log'
EOF
sudo tee /etc/systemd/system/lfcs-timer-test.timer >/dev/null <<'EOF'
[Unit]
Description=Run lfcs-timer-test every 5 minutes

[Timer]
OnCalendar=*:0/5
Persistent=true

[Install]
WantedBy=timers.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now lfcs-timer-test.timer
systemctl list-timers | grep lfcs

6. systemd targets

Boot target is the systemd equivalent of an old-style runlevel.

Read and change the default target (identical on both distros)
systemctl get-default
systemctl list-units --type=target
sudo systemctl set-default multi-user.target
systemctl get-default

Verify your work

Run these before you consider the lab finished.

  1. systemctl list-timers | grep lfcs-timer-test
  2. crontab -l | grep lfcs || crontab -l
  3. cat /tmp/cron-system.log 2>/dev/null || echo 'wait up to 5 minutes for the first cron run'
  4. systemctl get-default
Break it, then fix it

Break:

sudo systemctl mask lfcs-timer-test.timer

What you'll see: The timer no longer shows in systemctl list-timers, and enable --now silently refuses to start it — masking is stronger than disabling.

Fix:

sudo systemctl unmask lfcs-timer-test.timer
sudo systemctl enable --now lfcs-timer-test.timer

Why it matters: Masked units are a common trap: disable lets you re-enable normally, but a masked unit ignores enable and start until it's explicitly unmasked. Confusing the two costs time under pressure.
