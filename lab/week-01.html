Lab guide 1

Shell, Permissions, and Text Processing

The commands you'll use in every other week, drilled on both Ubuntu and Rocky from day one.

8-10 hours Both lab machines installed and reachable
Before you start
  • Both lab machines installed — one Ubuntu, one Rocky Linux
  • You are logged in as a non-root user with sudo rights on both
  • Take a snapshot of both machines. You will break things on purpose.

1. Find your way around

Prove to yourself where things live. The exam assumes you can navigate without thinking about it.

Where am I, and what is here? (both distros)
pwd
ls -la /etc | head
ls -ld /var/log /usr/share/doc /home
Follow a file back to the package that owns it — Ubuntu
which sshd || command -v sshd
ls -l /usr/sbin/sshd
dpkg -S /usr/sbin/sshd
Follow a file back to the package that owns it — Rocky
which sshd || command -v sshd
ls -l /usr/sbin/sshd
rpm -qf /usr/sbin/sshd

2. Redirection and pipes

Every one of these appears on the exam by name. Run each and read the result before moving on.

Standard output, append, and standard error
ls /etc > ~/etc-list.txt
ls /nope 2> ~/errors.txt
ls /etc /nope > ~/both.txt 2>&1
echo 'appended line' >> ~/etc-list.txt
wc -l ~/etc-list.txt ~/errors.txt ~/both.txt
Pipe into a filter, and tee to a file while still seeing output
ps aux | wc -l
ps aux | tee ~/procs.txt | grep -c sshd

3. grep and regular expressions

Anchors, character classes, and quantifiers cover almost everything the exam asks of you.

Anchors and case
grep '^root' /etc/passwd
grep 'bash$' /etc/passwd
grep -i 'ROOT' /etc/passwd
Character classes and quantifiers
grep -E '^[a-z]+:x:[0-9]{4,}:' /etc/passwd
grep -E 'nologin|false' /etc/passwd | wc -l
Recursive search, with filename and line number
sudo grep -rn 'PermitRootLogin' /etc/ssh/ 2>/dev/null

4. Files, directories, and links

Note carefully what happens to each link type when the target disappears. That difference is testable.

Create a working tree
mkdir -p ~/lab01/{src,dst}
echo 'original content' > ~/lab01/src/original.txt
cp ~/lab01/src/original.txt ~/lab01/dst/copy.txt
mv ~/lab01/dst/copy.txt ~/lab01/dst/renamed.txt
Hard link versus symbolic link
ln ~/lab01/src/original.txt ~/lab01/src/hardlink.txt
ln -s ~/lab01/src/original.txt ~/lab01/src/symlink.txt
ls -li ~/lab01/src/
Break the target and see which link survives
rm ~/lab01/src/original.txt
cat ~/lab01/src/hardlink.txt
cat ~/lab01/src/symlink.txt
Worth knowing

The hard link still prints the content because it points at the same inode. The symlink is now dangling and fails. Being able to explain that out loud, on either distro, is the point.

5. Permissions and ACLs

Set the same permission set both ways so octal and symbolic become interchangeable, then layer an ACL on top.

Symbolic and octal, same result
touch ~/lab01/perms.txt
chmod u=rw,g=r,o= ~/lab01/perms.txt
ls -l ~/lab01/perms.txt
chmod 640 ~/lab01/perms.txt
ls -l ~/lab01/perms.txt
Grant a second user access without touching the group
sudo setfacl -m u:adm:rwx ~/lab01/perms.txt 2>/dev/null || sudo setfacl -m u:$(id -un):rwx ~/lab01/perms.txt
getfacl ~/lab01/perms.txt

6. Archives

All three compression tools are named in the objectives. Create and extract with each.

tar with gzip and with bzip2
tar -czf ~/lab01-gzip.tar.gz -C ~ lab01
tar -cjf ~/lab01-bzip2.tar.bz2 -C ~ lab01
ls -lh ~/lab01-*
Inspect before extracting, then extract elsewhere
tar -tzf ~/lab01-gzip.tar.gz | head
mkdir -p ~/restore
tar -xzf ~/lab01-gzip.tar.gz -C ~/restore
ls -R ~/restore | head

7. Remote access and switching users

You'll use this connection in most later labs, so confirm it works now.

Connect to the second machine and come back
ssh $(whoami)@<other-machine-ip> 'hostname; uptime'
ssh $(whoami)@<other-machine-ip>
Switch users properly
su - $(whoami)
sudo -i
whoami
exit

8. Answer your own questions

This is the habit that matters most. In the exam there is no internet, only these.

Search by keyword, then read the right section
man -k passwd | head
man 5 passwd
man 1 passwd
The documentation that ships with packages
ls /usr/share/doc | head -20

Verify your work

Run these before you consider the lab finished.

  1. grep -c '' ~/etc-list.txt # the file exists and has lines
  2. ls -li ~/lab01/src/ # hardlink shares an inode with nothing now; symlink is broken
  3. getfacl ~/lab01/perms.txt # the ACL entry is present
  4. tar -tzf ~/lab01-gzip.tar.gz >/dev/null && echo 'archive readable'
Break it, then fix it

Break:

chmod 000 ~/lab01/dst

What you'll see: You can no longer list or enter the directory, even though you own it.

Fix:

chmod 755 ~/lab01/dst

Why it matters: Owning a file does not grant access; the permission bits still apply to you. This exact pattern shows up as a "diagnose and correct a permission problem" task.
