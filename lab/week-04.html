Lab guide 4

Packages, the Kernel, and Backups

Install and update software on both families, work with kernel modules, and back up before you break anything.

8-10 hours Week 3 complete
Before you start
  • Both machines up and reachable over the internet for package installs

1. Install, update, and remove a package

Same concept, different tool. Know both cold.

Ubuntu / Debian — apt
sudo apt update
sudo apt install -y tree
tree --version
sudo apt remove -y tree
Rocky / RHEL — dnf
sudo dnf check-update
sudo dnf install -y tree
tree --version
sudo dnf remove -y tree

2. Add and manage a third-party repository

The repo config file lives in a different place, but the workflow is the same.

Ubuntu / Debian — Add a PPA-style / custom apt source
curl -fsSL https://example-repo.invalid/key.gpg 2>/dev/null | sudo gpg --dearmor -o /usr/share/keyrings/example.gpg || true
echo 'deb [signed-by=/usr/share/keyrings/example.gpg] https://example-repo.invalid/ stable main' | sudo tee /etc/apt/sources.list.d/example.list
apt-cache policy 2>/dev/null | head -5
Rocky / RHEL — Add a .repo file
sudo tee /etc/yum.repos.d/example.repo >/dev/null <<'EOF'
[example]
name=Example Repo
baseurl=https://example-repo.invalid/rocky/
enabled=1
gpgcheck=0
EOF
dnf repolist

3. Kernel modules

Same tools on both distros — modules are a kernel concept, not a distro one.

List, inspect, load, and unload a harmless module
lsmod | head
modinfo dummy 2>/dev/null | head -8
sudo modprobe dummy
lsmod | grep dummy
sudo rmmod dummy

4. Kernel parameters with sysctl

Runtime change first, then make it survive a reboot.

Read, change at runtime, then persist it
sysctl net.ipv4.ip_forward
sudo sysctl -w net.ipv4.ip_forward=1
echo 'net.ipv4.ip_forward = 1' | sudo tee /etc/sysctl.d/99-lfcs-lab.conf
sudo sysctl --system | grep ip_forward

5. Back up and restore

The exam won't name a specific backup tool — it wants you to prove data survives.

A full backup with tar, and a mirror with rsync
mkdir -p ~/backup-target
sudo tar -czf ~/backup-target/etc-full-$(date +%F).tar.gz /etc 2>/dev/null
ls -lh ~/backup-target/
sudo rsync -a /etc/ ~/backup-target/etc-rsync/ 2>/dev/null | tail -5
Prove the restore actually works
sudo mkdir -p /tmp/restore-test
sudo tar -xzf ~/backup-target/etc-full-$(date +%F).tar.gz -C /tmp/restore-test
diff -rq /tmp/restore-test/etc /etc | head -5 || echo 'no meaningful differences'

Verify your work

Run these before you consider the lab finished.

  1. lsmod | grep dummy && echo 'still loaded — you forgot to rmmod' || echo 'clean'
  2. sysctl net.ipv4.ip_forward # should read 1
  3. ls -lh ~/backup-target/etc-full-*.tar.gz
  4. diff -rq /tmp/restore-test/etc /etc | wc -l
Break it, then fix it

Break:

sudo mv /etc/sysctl.d/99-lfcs-lab.conf /etc/sysctl.d/99-lfcs-lab.conf.bak
sudo sysctl -w net.ipv4.ip_forward=0

What you'll see: IP forwarding is off again, and it will come back off on every future reboot because the persistence file is gone.

Fix:

sudo mv /etc/sysctl.d/99-lfcs-lab.conf.bak /etc/sysctl.d/99-lfcs-lab.conf
sudo sysctl --system | grep ip_forward

Why it matters: A sysctl -w change without a matching file in /etc/sysctl.d/ never survives a reboot. This is the exact same "persistence" trap that shows up across the whole exam — a runtime change alone is worth nothing.
